## Набор сценариев проверки

| ID | Проверяемый сценарий | Ожидаемый результат |
|---|---|---|
| TC-001 | Пользователь отправляет запрос со всеми обязательными параметрами | Создан черновик консолидированного заказа |
| TC-002 | В запросе отсутствует обязательное поле или задано недопустимое значение | Система возвращает перечень ошибок и не создаёт исполняемый заказ |
| TC-003 | Заказ проходит от создания до получения результатов | Все позиции, подзаказы, попытки и результаты связаны с исходным заказом |
| TC-004 | Запрос включает продукты двух поставщиков | Созданы позиции и минимум два связанных подзаказа |
| TC-005 | Проверяются атрибуты созданных подзаказов | Для каждого подзаказа сохранены поставщик, результат, объём, единица, срок и условия приёмки |
| TC-006 | В заказе есть независимые и зависимые подзаказы | Независимые запускаются параллельно, зависимый — после получения необходимого результата |
| TC-007 | Пользователь подтверждает рассчитанные условия | Подзаказы создаются и передаются выбранным поставщикам |
| TC-008 | Два независимых подзаказа готовы к размещению | Оба направляются поставщикам без последовательного ожидания |
| TC-009 | Поставщик принимает подзаказ и возвращает свой идентификатор | Сохранены внутренний и внешний идентификаторы |
| TC-010 | Поставщик принимает, отклоняет или запрашивает уточнение | Система фиксирует соответствующий исход и обновляет состояние подзаказа |
| TC-011 | Поставщик не отвечает в срок | Срабатывает тайм-аут и регистрируется нарушение условия исполнения |
| TC-012 | Пользователь открывает карточку заказа | Отображаются общий статус, подзаказы, прогресс, результаты и отклонения |
| TC-013 | Статус поступает через callback либо обнаруживается опросом | Система асинхронно принимает и обрабатывает изменение |
| TC-014 | Поступает внешнее событие поставщика | Событие связано с правильными заказом, подзаказом и попыткой |
| TC-015 | Одно событие или результат поступает повторно | Результат, объём и переход состояния учитываются один раз |
| TC-016 | Два поставщика используют разные обозначения одинакового статуса | Оба статуса преобразуются в единое внутреннее состояние |
| TC-017 | Получена только часть обязательных результатов | Переход к итоговой проверке и агрегации не выполняется преждевременно |
| TC-018 | Поставщик передаёт результат, метаданные и фактический объём | Все сведения регистрируются в соответствующем подзаказе |
| TC-019 | Получен корректный, а затем заведомо некорректный результат | Корректный результат принят, некорректный отклонён с указанием причины |
| TC-020 | A исполнен успешно, B завершился ошибкой | Результат A сохраняется; отмена успешной ветви не происходит |
| TC-021 | Подзаказ исполнен полностью либо частично | Все пять видов объёма рассчитаны и сохранены |
| TC-022 | Позиции заданы в разных единицах измерения | Для каждой позиции используется согласованная единица без смешения значений |
| TC-023 | Часть переданного объёма отклонена проверкой | В исполненный объём входит только принятая часть |
| TC-024 | Получены фактические объёмы по нескольким позициям | Корректно рассчитан процент каждой позиции и заказа в целом |
| TC-025 | Все обязательные результаты приняты | Создан единый комплект с файлами, метаданными, описью и отчётом |
| TC-026 | Проверяются отказ, техническая ошибка, нарушение условий и тайм-аут | Каждый тип исключения обнаруживается и классифицируется |
| TC-027 | A исполнен, обязательный B завершён ошибкой | Заказ получает промежуточное состояние «Частичный сбой» |
| TC-028 | Зарегистрирован частичный сбой | Сохранены тип, источник, время, объём, успешные результаты и принятое решение |
| TC-029 | Для сбоя доступны разные способы восстановления | По правилам выбирается повтор, замена, уточнение, продолжение или решение пользователя |
| TC-030 | Повторные попытки несколько раз завершаются ошибкой | Соблюдаются интервалы и лимит; после исчерпания выбирается следующее действие |
| TC-031 | После сбоя выбран альтернативный поставщик | Замещающий подзаказ связан с исходным, его результат учитывается вместо неуспешного |
| TC-032 | Замена меняет цену, срок, состав или характеристики | Исполнение ожидает повторного подтверждения пользователя |
| TC-033 | Восстановление невозможно, но доступен результат A | Пользователь может принять частичный комплект или завершить заказ как неисполненный |
| TC-034 | Для заказа применяются правила выбора и коррекции | Используется активная версия формализованного правила |
| TC-035 | Два заказа конкурируют за один ограниченный ресурс | Сформирован однозначный порядок с учётом приоритета, срока и времени регистрации |
| TC-036 | Система выбирает поставщика, приоритет или коррекцию | В аудите сохранены версия правила и понятное обоснование выбора |
| TC-037 | Заказ проходит ключевые состояния | Пользователь получает необходимые уведомления, а журнал содержит переходы и действия |
