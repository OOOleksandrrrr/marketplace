# Оркестрация консолидированного заказа

Раздел содержит описание и модели ядра системы, которая принимает единый запрос пользователя, декомпозирует его на подзаказы минимум двум поставщикам, координирует исполнение и агрегирует результаты.

## Сценарии

В штатном сценарии два подзаказа исполняются разными поставщиками параллельно. Система асинхронно получает результаты, проверяет их, фиксирует фактические объёмы и формирует единый комплект.

В сценарии частичного сбоя результат поставщика A сохраняется, а для подзаказа B обрабатывается ошибка или тайм-аут. Возможные корректирующие действия: повторная попытка, замена поставщика или передача решения пользователю.

## Состояния заказа

- **Черновик** — запрос редактируется;
- **На проверке** — выполняется валидация;
- **Декомпозиция** — формируются позиции и подзаказы;
- **Ожидает подтверждения** — пользователь проверяет условия;
- **Размещается** — подзаказы направляются поставщикам;
- **В исполнении** — поставщики выполняют подзаказы;
- **Частичные результаты** — получена часть обязательных результатов;
- **Агрегация** — результаты объединяются;
- **Проверка результата** — проверяются полнота, формат и условия исполнения;
- **Частичный сбой** — система пытается восстановить исполнение;
- **Коррекция исполнения** — выполняется повтор или замена поставщика;
- **Ожидает решения** — требуется решение пользователя;
- **Исполнен**, **Частично исполнен**, **Не исполнен**, **Отменён** — итоговые состояния.

## Открытие файлов

- `.bpmn` открываются в Camunda Modeler через **File → Open File**;
- `.drawio` открывается в diagrams.net через **File → Open From → Device**;
- `.png` предназначены для быстрого просмотра;
- `.svg` удобно использовать в отчётах и презентациях.
